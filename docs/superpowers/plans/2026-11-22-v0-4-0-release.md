# Archive v0.4.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish Archive `v0.4.0` with the open-book brand mark, an arm64-only Android Release APK signed by a real release key, an unsigned iOS IPA, and the Android background/resume create-trip crash removed.

**Architecture:** Keep the Expo CNG project under `src/`; native projects remain disposable outputs of `expo prebuild`. Isolate the crash fix in a pure submit-outcome contract so the successful navigation path never resets the outgoing modal's busy state in the same frame, and render every brand asset from one checked-in SVG. Configure the generated Android Gradle project from CI-only environment variables, verify the resulting APK's signer/ABI/version/size before upload, and publish only after an affected-device release-candidate check.

**Tech Stack:** Expo SDK 58, React Native 0.88.1, React Navigation native stack, Zustand, Node 24 test runner, Sharp 0.35.5, Expo Prebuild, Gradle, `apksigner`, GitHub Actions, GitHub Releases.

**Spec:** `AGENTS.md`, `docs/standards/README.md`, `docs/standards/glossary.md`, `src/app.json`, and the `v0.4.0` release constraints recorded in this plan's Global Constraints.

## Global Constraints

- The public remote is `https://github.com/scapking/archive`; do not change repository visibility.
- `v1.0.0` must remain at commit `9a0c6f4b3da0ea8bcbb96b263d5c08e39cec878c`; never move, delete, or recreate that tag.
- The new release tag is exactly `v0.4.0`; `src/app.json` version and `src/package.json` version must both be `0.4.0`.
- Preserve the existing application identifiers `com.anonymous.archive` on Android and iOS; set Android `versionCode` to `4` and iOS `buildNumber` to `"4"`.
- The Android artifact is a Release APK, contains only `arm64-v8a`, is at most 120 MiB, and is signed by a release key whose certificate differs from the generated Expo/React Native debug key.
- The iOS artifact remains an unsigned compile-only IPA and must not be described as App Store- or TestFlight-installable.
- Android keystore bytes, store password, key alias, and key password may exist only in GitHub Secrets and temporary runner process environment/files; they must never enter the repository, workflow YAML, URLs, logs, artifacts, commit messages, or Release notes.
- All GitHub Actions remain pinned to full commit SHAs; Release creation uses only `${{ github.token }}` and `contents: write` in the Release job.
- The brand mark is a text-free, flat, symmetrical open book with a center spine: warm off-white `#F7F2E8`, deep ink `#202522`, no gradients, shadows, whale, or decorative text.
- The crash fix addresses the proven create-submit transition race; do not apply the `react-native-screens#4157` translucent-modal patch because `trip/new` is an opaque modal and that code path is not the failing one.
- The Expo project root is `src/`; run package commands from `src/`.
- New source files follow the repository naming and layering standards; no business-domain code enters `src/core/`.

## Review Focus

- A successful create/edit resets the outgoing modal's busy state in the same React frame as `router.replace`/`safeBack`, allowing Fabric to mutate a screen retained by the native removal transition; Task 1 must fail if that reset is requested.
- An APK contains `armeabi-v7a`, `x86`, or `x86_64`, uses the debug certificate, exceeds 120 MiB, or reports a version other than `0.4.0`/build `4`; Task 5 must reject it before upload.
- A keystore, password, alias, key password, PAT, or authenticated remote URL leaks into tracked content or Actions output; Tasks 4–6 must scan and prove absence.
- The adaptive foreground is clipped by the launcher mask, the monochrome alpha mask is empty, the dark splash loses the book, or any whale pixels remain; Task 2 must verify dimensions, safe area, alpha, and canonical rendering.
- A tag/version mismatch, an accidental `v1.0.0` move, or an APK whose filename says `0.4.0` but whose manifest says otherwise is published; Tasks 3 and 8 must check both metadata layers.

```ts
export type TripSubmitResult =
    | { kind: 'created'; tripId: string }
    | { kind: 'updated' }
    | { kind: 'failed' };

export interface TripSubmitOptions {
    tripId?: string;
    create(): Promise<{ id: string } | null>;
    update(): Promise<boolean>;
    onCreated(tripId: string): void;
    onUpdated(): void;
    onFailed(): void;
}

export async function runTripSubmit(options: TripSubmitOptions): Promise<TripSubmitResult>;
```

When `tripId` exists, call `update`; otherwise call `create`. On success, call exactly one success callback (`onCreated` or `onUpdated`) and never `onFailed`. On `false`/`null`, call `onFailed` and return `failed`. Let unexpected rejections propagate unchanged.
